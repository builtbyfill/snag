# Build Checklist

Filip runs all git himself (staging, commits, push); after each slice the agent lists the files that belong in the commit and suggests the message (his standing rule overrides the skill's automatic commit).

## Revisions

- Scaffold in a scratch folder and move it into the repo root instead of `npx create-next-app@latest snag` — the spec's command would create a nested `snag/` folder, and create-next-app refuses to scaffold into a folder that already holds `devpost/`, `.agents/` and `CONTEXT.md`.
- `ClaudeProvider` sends `zodOutputFormat(ExtractionOutput)` through `messages.create()` and returns the raw text; `policy.ts` does JSON parse → normalize → `ExtractionOutput.safeParse` — in `@anthropic-ai/sdk` 0.135 `messages.parse()` throws an `AnthropicError` on Zod failure instead of returning `parsed_output: null`, and it validates before normalization, so enum casing ("High") would fail instead of being normalized.
- Eval `location` matches when the model's value **contains** an accepted string (case-insensitive, whitespace collapsed) — the spec's "normalized value is in `accept`" read as exact equality would almost never match free-text locations such as `Zakažite termin dialog, step 3 "Podaci" (Vaši podaci)`.
- Eval cases carry a required `author` plus `nonTechnicalAuthor: true|false`, and the summary counts real non-technical authors; `mustMention` entries accept synonym lists — Filip's slice-2 review: the README claim depends on authorship, and keyword-only title matching was too strict for equivalent wording ("Podaci" for "details").
- Compose `db` publishes `127.0.0.1:5433:5432` and host-dev `DATABASE_URL` uses port 5433 — the spec's `db` service had no `ports`, but host-side `npm run dev`, migrations and seed need to reach Postgres, and another local project (piz-erp-dev) already holds 5432. Inside Compose the app still uses `db:5432`.
- Client IP is always the first `x-forwarded-for` value; locally a client could spoof it (Filip accepted this) — a server action cannot read the socket address, and Next 16 only fills `x-forwarded-for` from the socket when the request has none (`next/dist/server/base-server.js`). Behind Caddy the header is overwritten with the real address. `TRUST_PROXY` is dropped from env and `.env.example` because it no longer changes behavior.
- `next.config.ts` uses `experimental.serverActions.bodySizeLimit` — on Next 16.4 the key is still under `experimental`, not top-level `serverActions` as the spec assumed.
- `cacheComponents` and `partialPrefetching` removed from `next.config.ts` (Filip's decision) — the Next 16.4 scaffold enables them, which requires `<Suspense>` around every database/cookie read and makes a streamed `notFound()` answer 200 instead of 404; all Snag screens are per request, so nothing gains from a static shell.
- shadcn dependencies installed with `npm install` and the CLI run from `node_modules/.bin` — `npx shadcn init` failed with `EALLOWSCRIPTS` because the global `~/.npmrc` `allow-scripts` entry is passed to the nested npm as a flag. shadcn 4.22 uses the `cn` package (shadcn-ui/cn) instead of `clsx` + `tailwind-merge`.
- Client page copy is Bosnian by default with a complete English set in `lib/i18n/client-copy.ts`; the server returns error codes instead of sentences; Send always looks active; placeholder starts with "npr." in a lighter `ink-faint` token; reassurance line under Send — Filip's review of the slice-3 page (his clients are local; a pale button read as disabled although tapping it is what shows the hints).
- New slice 3a (client chat) inserted before slice 4; slice 7 becomes dashboard chats and takes over the authenticated image route from slice 8; slice 8 opens from a ticket card with "Back to chat"; the cut order in `scope.md` gains the chat extras — Filip's direction on 2026-10-17 that Snag should feel like a chat on both sides, accepted at about +1.5 days. Client header shows `DEVELOPER_NAME`; Done tickets stay in the dashboard thread, muted.
